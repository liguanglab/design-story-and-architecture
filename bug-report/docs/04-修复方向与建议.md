# 修复方向与建议（服务端 / 非客户端可修的部分）

> 客户端两条已本地修好并验证（见 `fix-verification.md`）。下面这些**改客户端修不了**，
> 只能给方向 + 验收标准。每条都写"怎么算修好"，方便对方照着改、照着验。

---

## 1. 余额充足却报 `NO_CREDITS`（tier 限制被误报）

**根因**：额度按 model tier 授予（`grants[].limits.allowed_model_tiers: ["t2"]`），
但请求只校验"总余额 > 0"，被后端拒绝时统一回 `credits_insufficient`。

**建议**
```
· 错误码拆分：INSUFFICIENT_TIER（档位不允许） / NO_CREDITS（真没钱）
· 提交前用 grants[].limits.allowed_model_tiers 预检，直接拒绝并说明
· 文案示例：「免费额度仅支持 t2 档模型；图片模型需要付费额度」
```

**验收标准**
```
免费号请求图片模型 → 收到 INSUFFICIENT_TIER + 明确文案；
且画布上不产生"✗ no credits"残卡（现在是每次失败留一张）
```

---

## 2. 0 字节文件 → HTTP 413

**根因**：上传链路未在客户端判空，服务端对空 body 回了 413（语义应为"请求体过大"）。

**建议**
```
· 前端：file.size === 0 → 直接提示"文件为空"，不发请求
· 服务端：空文件返回 400 + EMPTY_FILE，不要用 413
· 失败卡片提供"删除"，同类失败不重复堆叠
```

**验收标准**
```
传 0 字节文件 → 提示"文件为空"；列表里不新增卡片；重复传不产生第二张失败卡
```

---

## 3. 50MB 文件静默消失

**根因**：超大文件被丢弃，但前端没有反馈（无 card、无 toast、无网络错误）。

**建议**
```
· 前端加上限（例如 20MB）并即时提示"超过 X MB"
· 服务端超限返回 413 + FILE_TOO_LARGE，前端展示 code
```

**验收标准**
```
传 50MB → 立刻看到"超过上限（X MB）"；不会出现"什么都没发生"
```

---

## 4. 内容相同的文件被静默丢弃

**根因**：按内容去重（hash 命中即跳过），但没有任何提示。

**建议**
```
· 命中去重时提示「已存在相同内容的文件：<文件名>」，或允许重复并标注"副本"
```

**验收标准**
```
同一内容换名字传第二次 → 出现提示；列表里能看到"已存在"或新增副本
```

---

## 5. 画布并发写入无版本控制（最严重）

**根因**：写入接口 `POST /user/batch-update-nodes` 与
`POST /creator/conversations/{id}/canvas` 的 payload 与请求头里**都没有版本/条件字段**
（无 version、无 If-Match、响应无 ETag），两端都 2xx，后写覆盖先写。

**建议**
```
· 节点增加 version（或 updated_at 单调递增）
· 写入要求 If-Match: <version>；不匹配返回 409 Conflict + 当前 version
· 前端收到 409 时提示"该卡片已被其他窗口修改"并刷新该节点
· 或改用 CRDT/OT（成本高，可先做乐观锁）
```

**验收标准**
```
两窗口同时拖同一张卡 → 至少一端收到 409 或"已被修改"提示；
服务端最终值等于"被接受的那一次"，且被拒的一方知道自己被拒
```

## 6. 提交后 3~5 秒被杀 → 卡片永久卡死

**根因**：卡片先建占位、再异步生成；客户端进程被杀后没人落账，服务端也没有超时兜底。

**建议**
```
· 提交后先在本地落一条"已提交待落账"（源码 retry 路径已有类似注释，可复用）
· 服务端对"长期 running 且无心跳"的卡片做超时回收（如 10 分钟）→ 置为 failed 可重试
```

**验收标准**
```
提交后 3 秒 kill 进程 → 60 秒内该卡片变成"失败可重试"，不是永远 running
```

---

## 7. 没有"重跑节点"入口 / 上游变更不传播

**根因**：节点依赖只是画布上的连线；删除上游后下游仍 `finished`、无失效标记；
且 UI 没有"重跑节点"，只有"复用（带进聊天）"和"引用该节点生成（造新节点）"。

**建议**
```
· 增加节点级「重新生成」（同 prompt 重跑，保留版本历史）
· 上游节点内容变更/删除时，下游节点标记"上游已变更，结果可能过期"
· 可选：提供"级联重算"按钮
```

**验收标准**
```
改 A 的 prompt 并重跑 → B、C 出现"上游已变更"标记（或自动重算）；
删除 A → B 显示"上游不存在"而不是继续 finished
```

---

## 8. 刷新 / 关页面不取消生成，照常全额计费

**根因**：生成在服务端跑，刷新只是断开前端；产品没有提示，也没有真正的取消入口。

**建议**
```
· 生成中刷新/关闭时提示「任务将在后台继续并计费」
· 或提供真正的取消（停止并退款/不计费），与"停止回复"语义一致
```

**验收标准**
```
生成中点刷新 → 出现"后台继续并计费"的提示；
点"停止回复" → 不计费（现在已符合，实测 0.00）
```

---

## 9. 断线无"网络中断/重连"提示

**根因**：断网后只显示"琢磨中"计时，恢复慢（15 秒断线 40~100 秒续写；60 秒断线有一次 120 秒窗口内没动）。

**建议**
```
· 流式中检测连接失败 → 显示"网络中断，正在重连（第 N 次）"
· 恢复后如遇截断，标注"回复可能不完整"并提供"继续生成"
```

**验收标准**
```
断网 15 秒 → 界面出现"网络中断/重连中"；恢复后正常续写
```

---

## 优先级建议（按商业影响）

```
P0：5（并发无版本）—— 直接丢用户数据
P0：1（档位误报）—— 免费用户完全无法出图，且信息误导
P1：2 / 3 / 4（上传三连）—— 用户不知道发生了什么，反复重试
P1：6（卡死）—— 脚本/CI 会挂住
P2：7（重跑/失效传播）、8（计费提示）、9（断线提示）
```
