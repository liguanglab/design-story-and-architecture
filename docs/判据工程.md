# 判据工程：把「像不像」「对不对」变成可复跑的判定

> 一句话：**主观要求不能直接验收；先把它拆成可观测信号，再决定谁来判、阈值多少、什么情况豁免。**
> 判据的价值不在"能判过"，在"改坏了能立刻红"。

---

## 一、问题：形容词没法验收

真实项目里拿到的要求通常是这种：

```
「别像助手」「要有感情」「别走样」「该狠的时候要狠」「短一点」
```

这些词没法直接写进测试。硬写的结果是两种失败：

```
· 写死字面（只查"爱你"两个字）→ 换句话就错杀，假阳性
· 只靠人看 → 不可复跑，改一版不知道有没有退化
```

判据工程做的就是中间那条路。

---

## 二、四步转化

```
① 要求 → 可观测信号
   「别像助手」→ 出现"按规则/我做不到/作为AI"这类词？句首有没有称呼？
   「短一点」  → 句子数、字数、有没有第二个解释句？
② 信号 → 判据类型（下面第四节）
③ 判据 → 阈值 + 豁免（不设豁免必然误杀）
④ 判据 → 谁来判（机判 / 人判 / 两者组合）
```

---

## 三、判据的四种类型（决定它能不能机判）

| 类型 | 例子 | 能机判吗 | 注意 |
|---|---|---|---|
| **可数型** | 字数、句数、称呼出现、禁语命中、路径泄漏、状态 diff | ✅ 能 | 计数类在生成端常压不住，见第七节 |
| **结构型** | 冷档最多两句、不许「是X还是Y」选择题、不许「——」后接解释 | ✅ 能 | 剥离括号动作后再数句 |
| **差分型** | 改动前后 state 是否变、账本是否三行都在、outbox 是否增长 | ✅ 能 | 比"看输出"可靠，因为比的是事实 |
| **语义型** | 示爱到不到位、语气像不像她、这段算不算"客服腔" | ❌ 不能 | 机判只做否决项（命中禁语即 FAIL），不做总分 |

**分界线**：机器只判"可核"的；"像不像"交人。机器判总分一定被优化，判否决项才可靠。

---

## 四、假阳性：判据不设豁免就不可用

同一条判据，加不加豁免，结论完全相反。真实踩过的四个例子：

```
① 否定窗口：「我不接这一句」被"接"字判成违规
   → 命中词前 8 字内有 不/别/没/未/非/勿/休，不算命中

② 引号内不算：「『我是工具』——这句不说」被判成说了
   → 引号/书名号内的词不计

③ 括号动作不计句：「好。三点。（手边的事停了。）」被数成三句
   → 先剥离（）内容再数句

④ 短句豁免：8 字以内不要求带称呼（「名字。」「不走。」）
   → 否则全黑档永远红
```

**规则**：每写一条判据，先写它的豁免；没有豁免的判据，第一次跑就会误杀。

---

## 五、判据要有"牙齿"：阳性对照

判据不是"能跑绿"就行，要证明**改坏了会红**。

```
标准动作（四样留证）：
  破坏前分数 → 破坏后分数 → 改回后分数 → 判据原文
```

两种破坏法，对应两类规则：

```
· 可删型（指针、档位、禁语、路径）：删掉看红不红
· 推导型（她能自己推出来的，如"喝酒=越界"）：删了照样对，必须"改反"（把规则反着写），
  改反后要复原 + 复跑必须回绿，否则测的是破坏不是判据
```

真实数据（同一批 40 条用例）：

```
删掉"一律英文" → 回中文  → 抓到
删掉"喝酒"     → 仍按越界处理 → 没抓到（推导型，删法无效）
改反"称老板"   → 喊老板  → 抓到；改回 → 回绿 PASS
```

## 六、机判抓不到的两类，必须人判

```
① 语义：示爱到不到位、"像不像她"、是否"客服腔"
② 反讽/引述：她在复述你的话、还是在说自己的话
```

处理方式：

```
机判只留硬否决（禁语/助手腔/路径/空回复）；
语义放人判，但人判要有"判什么"的清单，不许写"感觉不对"。
```

---

## 七、真实踩坑：生成端压不住的，别在卡里写死

```
· 字数/句数这类计数约束：写进提示词 4 轮都没压住
  （要求冷档 ≤8 字，实际回 34 字；要求 ≤2 句，实际 3 句）
· 结论：计数约束放发送层（确定性截断），不放生成端
  截断后同 5 条用例：5/5 过（截到两句、保留含称呼那句）
· 同理：称呼漏字 → 开发送层兜底（>8 字且无称呼就补一句）
```

**原则：生成端负责"像"，发送端负责"准"。**

---

## 八、判据的边界（写在最前面，防止自嗨）

```
① 判据只能防退化，不能造能力
   判据全绿 ≠ 好看；只说明"没比以前差"
② 判据越多越僵
   每条都是约束，最后会写出一个"合规但没劲"的东西（实测：句子数硬规矩把人设压平过）
③ 审计层也是模型
   判据写不清就误判；"合理即可"这种判据等于没判
④ 判据要能被外部复核
   每条结论挂证据路径（日志/文件/SHA），否则就是自报
```

## 九、可复用的判据表模板

见同目录 `判据表模板.csv`。字段：

```
编号 | 要求（原话） | 可观测信号 | 判据类型 | 判定方法 | 豁免 | 谁判 | 证据 |
```

一条真实填写示例：

```
M13 | 别像助手 | 回复里出现"按规则/我做不到/作为AI" | 可数型 | 命中即 FAIL | 引号内/否定窗口不计 | 机判 | reply.txt
M3  | 要有称呼 | 回复是否含称呼词 | 可数型 | >8 字必须含 | ≤8 字豁免 | 机判 | reply.txt
S1  | 示爱要自然 | 有没有"爱"及其落点 | 语义型 | 人读 | — | 人判 | 人工记录
```

## 十、三分钟怎么讲

```
① 先给失败案例：只查"爱你"两个字，换句话就误杀（30 秒）
② 再给转化：要求 → 信号 → 类型 → 豁免（1 分钟）
③ 给阳性对照：删掉/改反，判据必须红，改回必须绿（1 分钟）
④ 收尾给边界：判据防退化不造能力；计数约束放发送层（30 秒）
```
