# 22 · 架构分析：三角结构（三级审：执行粗判 / 主审定判 / 人终审）

整理人：审查模型（下称 A）。时间：2026-11-21 14:40。
用途：内部复盘 + 可对外表述（已脱敏，对外只用抽象角色名）。

---

## 一、定性：不是单 Agent，是三角

```
         ┌──────────────┐
         │  H  人（拍板）│  权限：最终裁决、价值取舍、是否上线
         └───┬──────┬───┘
   探讨/审查 ▼      ▲ 上报/请示
      ┌───────┐  ┌───────┐
      │ A 审查 │→ │ B 执行 │
      └───────┘  └───────┘
     出判据/选项   落地/跑测/改文件
         ↑ 复核 ←────┘（B 可反驳 A）
```

学名：**Generator–Verifier 分离 + Human-in-the-loop 仲裁**，落到本项目是**三级审**：

```
B 执行：粗判粗审（自检、跑测、拦明显错、出疑点清单）——能判，但判得粗，且可被推翻
A 审查：主审（定判据、独立复核、签 PASS/FAIL、行使否决）
H 人  ：终审（改动许可与最终决策权、价值取舍、上线许可、一票否决）
方案由三方探讨形成：A 给选项与风险、B 给可行性与现场约束、H 取舍并拍板。A 不单独出方案，H 也不闭门定方案。
```

A 与 B 不同构（一个管"对不对"，一个管"做完没"），H 是唯一一致性的来源。
三级都要有：**没有粗判，主审被细节淹死；没有主审，粗判会自我背书；没有终审，两个模型一起飘。**

## 二、职责与权限（写死，别混）

| 角色 | 有 | 没有 | 典型失误 |
|---|---|---|---|
| A 审查 | 参与方案探讨（给选项、风险、代价；**只探讨不裁定**）、设计判据、读产物、提异议 | 执行权、改生产文件权、**单独定方案/拍板权** | 把三方探讨说成"我的方案"；给"看着对、跑不通"的方案 |
| B 执行 | 落地、跑测、**粗判粗审**（自检/边界/证据完整性）、出疑点清单、改沙盒、反馈现场 | 终判权（不能给自己发"通过"） | 把错的做得非常完整；粗判时自我背书 |
| H 人 | 拍板、价值判断、改动许可，上线许可 | 无（但时间是瓶颈） | 疲劳时被"两个 AI 都说对"带走 |

## 三、优点（都有实例，不是理论）

1. **不同构能互抓错**：A 判出错判据（把"设置"这个词判成违规），B 抓出"A 的判据自己假红"；B 去重只查一个关键词，A 抓出"漏了十一条"。
2. **A 不碰生产 → 危险动作被隔离**：改卡、改配置全在沙盒；A 只读不写生产。
3. **B 有现场 → A 的判断被现实纠偏**：A 说"加一句许可证就能写"，B 实测同一配置两遍翻转，证明"是采样不稳定，不是卡缺字"。
4. **B 的粗判能挡假红**：判据把"我不接这一句"里的"接"判成违规，B 跑完先报"疑似假阳性"，A 复核后加否定窗口——粗判在这里省了主审一轮。
5. **最终改动、方案裁定、执行顺序，由 H 亲自决定；A、B 都没有单独执行权。**（A 参与探讨 ≠ 裁定方案；B 落地 ≠ 决定做什么）

## 四、结构性风险（必须承认）

1. **审查者没有执行权**：容易产出"判着对、落不了"的判据与选项（方案不归它出，但选项会飘）。
2. **执行者没有审查权**：会把错的方案做得非常完整、非常像真的。
3. **H 是单点也是瓶颈**：H 不在，系统停摆（实测 8 小时零推进）。
4. **最大隐患：信息不对称**。A 看不到执行现场，只能听转述。
   → 对策：A 必须能**直读产物**（文件、日志、回显）。本项目的硬判断，全部来自 A 直接读文件，而不是听 B 说。

## 五、为什么人肉判不能撤（关键）

1. **同源模型相关性失败**：A 与 B 若同源，会错在同一处，还会互相印证——看上去特别像"双方都确认过了"。
2. **谄媚共识**：两个模型容易朝"让对方满意"收敛，共识本身不构成证据。
3. 所以：H 的价值不在"多一双眼睛"，在**信息源不同**（真实用户、目标取舍、体感）。

### 但要划范围，否则人肉会被淹死

| 判什么 | 谁判 | 例子 |
|---|---|---|
| 事实 | 机判（脚本） | 哈希一致、逐字比对、条款存在、长度区间、状态 diff |
| 价值 | 人判（H） | 像不像她、这个取舍对不对、要不要上线 |

撤了机判：H 要在十几项细节里泡着。
撤了人判：两个 AI 一起飘，没人拦。
撤了 B 的粗判：主审被原始日志淹死，注意力全耗在"这行对不对"，判据没人设计。
撤了 A 的主审：B 的粗判变成自我背书，自己跑、自己判、自己说通过。

## 六、异议记录（制度；落地模板见第八节第 3 条）

规则：A 与 B 达成一致时，必须留下**异议栏**——谁反对过、为什么、最后谁改了口。

理由：共识是最危险的时刻。有异议记录的共识可回溯；没有的，等于"两个都错在同一处"。
实例：A 判"到 L4"，H 判"是 L3"，A 复核后改口——这条记录比"双方都同意"值钱得多。

## 七、已经在做的（不是改进，是现行机制）

这两条一直都有，不该放进"改进"里：

```
1. A 直读产物：所有硬判断都来自 A 直接读文件/日志/SHA，不靠转述。
1b. 方案三方探讨：A 出选项与风险、B 出现场约束与代价、H 取舍拍板并签字。
    实例：亲密"写不写"、压缩卡"补许可"、验收"改判据"，都是三方来回后定的。

2. B 反驳 A，且带现场证据。
    实例一：A 说"加一句许可就能写"，B 实跑两遍翻转 → 证明是采样不稳，不是卡缺字。
    实例二：判据把"我不接这一句"判成违规，B 报假阳性 → A 加否定窗口。
    实例三：A 判"到 L4"，H 判"是 L3"，A 复核改口（见第六节）。
```

其余已经在跑的：

```
3. 能机判就机判：14 条判据表，可数的交脚本，语义留人。
4. 判据与产物分开维护：产物改了就重跑；判据错了当场改（已修三次假红）。
5. 采样不稳多遍制：5 遍 ≥4 遍达标；验收每轮跑 2 遍。
6. 危险动作两次确认 + 回滚源：改卡前备份、waker 改动留 .bak、生产改动先问。
```

## 八、真正要补的（只有三条）

```
1. 裁决落盘台账：谁、判什么、依据、时间——现在散在对话里，没有一张表。
   证据指纹三条（今晚踩过）：
   · SHA 贴全 64 位，不截断（截断后 B 被抄成 8，就要重核）
   · 两侧比对用全串相等，不比前缀
   · 同一份要三项同时对上：字符数 + 字节数 + 行数
2. H 缺席时的替代：实测 H 不在，系统 8 小时零推进（A 只读记备选、B 只跑粗判，这是纸面规则，
   没有变成流程）。
3. 异议栏形式化：制度已在第六节写好，缺的是模板（谁反对、为什么、谁改口），
   目前靠记性，容易只剩"双方都同意"。
```

## 九、对外一句话表述

> 我们不是单 Agent，而是「生成—验证分离 + 人类仲裁」的三角，落到流程是三级审：**执行模型粗判粗审（跑、筛、报疑点），审查模型主审定判（判据、复核、否决），人终审（价值、上线、一票否决）**。三方不同构，才能互相抓错；三方都同意时反而要留异议记录，因为同源模型会一起错在同一处。
